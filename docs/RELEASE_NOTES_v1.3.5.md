# ChatInsight v1.3.5

## 修复

- 修复杂交分析仍固定按 14000 字符拆分历史的问题；分段策略现在与模型服务的最大输入 tokens 联动。
- 默认 350000 tokens 输入预算能够容纳的聊天会作为一份完整上下文直接进入单次分析请求。
- 不再为普通长度聊天额外发起多段 1800/2000 tokens 摘要请求。
- 只有聊天证据确实超过配置输入上限时才启用分层摘要。
- 分层摘要请求会携带前一段摘要，保持跨片段上下文连续；最终分析继续接收全部阶段摘要与近期原文。
- 分析预检新增“单次完整请求 / N 段分层摘要”策略展示，并据此计算预计请求数。
- 辅助摘要的单次输出预算由 1800/2000 提升到最多 8000 tokens，仅在超长历史确实需要分段时使用。
- 修复 `incomplete + max_output_tokens` 且响应同时包含 reasoning 与部分 message 时直接丢弃内容的问题。
- 模型已生成部分文本时会先尝试提高预算；无法继续提高时保留部分 JSON，并进入分析校验后的自动修复请求。

## 行为说明

- 图片分析仍按每批最多 4 张独立发送到视觉模型，因为文本模型请求不会直接携带全部原始图片。
- 截图识别、风格生成和超长历史摘要属于独立辅助任务，仍会产生单独请求；普通聊天分析在输入预算内只产生一次最终文本请求。
- 各请求仍是无服务端会话状态的独立 HTTP 调用，完整上下文由应用在本地组入请求，不依赖中转站保存上下文。
- 若中转站或模型实际输出上限低于应用配置值，首个结果可能被截断；应用会保留已有内容并尝试用更短的修复请求生成完整 JSON。

## 兼容性

- 未更改数据库结构、保险库格式、隐私密码或恢复码存储方式。
- 已配置的输入/输出 token 上限与旧数据保持兼容。

## 验证

- 单元测试覆盖 350K 输入预算下单次完整请求规划，以及超限历史分段后消息不丢失。
- TypeScript 严格类型检查、完整单元测试和 Electron E2E。
- 真实 NSIS 覆盖升级测试覆盖 v1.3.4 → v1.3.5 的已导入消息、隐私密码、恢复码和加密 API 凭据保留。

## 升级说明

- 关闭正在运行的 ChatInsight，使用 v1.3.5 安装包覆盖安装到 v1.3.4 的同一目录。
