# ChatInsight v1.3.3

## 修复

- Responses API 请求现在显式发送 `stream: true`，中转站调用记录会按流式请求处理，并使用现有 SSE 聚合器读取增量文本。
- 连接测试的最小输出预算从 16 提升到 1024，避免推理模型把全部预算用于 reasoning 后直接返回 `incomplete`。
- 上游明确返回 `incomplete_details.reason=max_output_tokens` 时，会自动提高输出预算并受控重试，最高 24000 tokens。
- 自动重试仅针对 token 耗尽，不会对鉴权失败、格式错误或普通网络错误额外提高预算。
- 其他 Responses 响应兼容、错误分类和脱敏诊断保持 v1.3.2 的行为。

## 使用与费用说明

- 首次请求仍使用调用点配置的输出预算；只有明确发生 `max_output_tokens` 耗尽时才可能发起额外请求。
- 推理模型的 reasoning tokens 计入输出预算；提高预算可能增加模型服务费用。
- 若中转站不支持 Responses 流式请求，会返回明确的服务错误，而不会再静默记录为非流式请求。

## 兼容性

- 未更改数据库结构、保险库格式、隐私密码或恢复码存储方式。
- 覆盖安装继续使用 v1.3.0 引入的原子数据目录保护策略。

## 验证

- 单元测试覆盖 `stream: true`、SSE 聚合、连接测试预算和 token 耗尽后的预算重试。
- TypeScript 严格类型检查、完整单元测试和 Electron E2E。
- 真实 NSIS 覆盖升级测试覆盖 v1.3.2 → v1.3.3 的已导入消息、隐私密码、恢复码和加密 API 凭据保留。

## 升级说明

- 关闭正在运行的 ChatInsight，使用 v1.3.3 安装包覆盖安装到 v1.3.2 的同一目录。
- 覆盖更新存在旧保险库时不能更换安装目录。
