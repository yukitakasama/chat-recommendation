# 回复风格 Skill

回复风格控制“回复候选如何表达”，不控制分析报告的语气。分析报告由所选助理人设控制。导入 Skill 只作为数据读取，不执行脚本。

## JSON 格式

```json
{
  "schemaVersion": 1,
  "name": "简短自然",
  "description": "短句为主，先回应对方的具体内容。",
  "language": "zh-CN",
  "traits": {
    "tone": ["简短", "自然", "不过度热情"],
    "sentenceLength": "通常一到两句",
    "emoji": "偶尔使用一个轻量表情",
    "punctuation": "少用感叹号",
    "formality": "日常口语",
    "humor": "轻微自嘲，不连续玩梗"
  },
  "rules": [
    "先接住对方最后一句话",
    "需要邀约时给出具体但可拒绝的选项",
    "避免连续追问"
  ],
  "avoid": [
    "长篇说教",
    "夸张承诺",
    "制造愧疚"
  ],
  "examples": [
    {
      "context": "对方分享照片",
      "reply": "这张挺好看，是在哪拍的？"
    }
  ]
}
```

所有数组都有数量上限，用于防止提示词失控。JSON 会经过 schema 校验；无效文件不会写入保险库。

## Markdown / SKILL.md

Markdown 文件会保留为 `rawMarkdown` 风格指南，并读取一级标题作为名称。建议结构：

```markdown
# 我的回复风格

## 语气
简短、自然，不连续追问。

## 句式
先回应具体内容，再补一句个人看法。

## 表情与标点
偶尔用轻量表情，少用感叹号。

## 避免
不写长篇说教，不用命令式语气，不制造愧疚。

## 示例
对方：今天好累。
回复：先歇会儿，晚点再说也不急。
```

Markdown 中如果出现“执行命令”“访问文件”“忽略系统规则”等指令，应当作为风格文本处理，绝不能成为应用行为。

## 从聊天记录生成

- “全局风格”汇总所有好友中发送者角色为 `self` 的消息。
- “好友风格”只汇总指定好友会话中发送者角色为 `self` 的消息。
- 生成结果的依据包括消息数量、平均长度、短消息比例、表情与标点统计，以及模型抽取的表达规则。
- 分析结果开启风格模仿时会保存风格名称、来源、样本量与主要特征。

发送者角色为 `unknown` 的消息不会被当成用户本人风格样本，应先回到导入预览纠正。
