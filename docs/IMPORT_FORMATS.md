# 聊天记录导入格式

## 导入批次

一次导入由聊天导出文件、图片和截图组成。应用先解析到预览，再由用户纠正发送者角色和文本，最后选择复制或移动并正式提交。

同一文件内容使用 SHA-256 去重。同名但内容不同的文件不会覆盖，内部使用唯一 Blob 路径。部分文件失败时，成功文件可以保留，失败文件逐项显示；移动模式下只有已加密保存并提交的对应源文件才会被删除。

## TXT

优先识别以下时间戳与发送者结构：

```text
2025-03-01 10:02:03 小林(123456)
这是消息正文
2025-03-01 10:03:04 我: 这是另一条消息
```

也兼容 `[2025-03-01 10:02:03] 小林: 内容`、`2025/03/01`、中文年月日等常见写法。多行消息会合并到上一条发送者。

发送者角色规则：

- 发送者与好友名称匹配：`other`
- `我`、`本人`、`自己`、`me`、`self`：`self`
- 系统名称：`system`
- 无法确认：`unknown`

`unknown` 会保留导入，但应在预览中纠正；否则基于本人消息的风格生成会跳过这些消息。

图片引用示例：

```text
2025-03-01 10:04:00 小林: [图片] 周末的照片.jpg
```

若批次中存在同名图片，会建立消息与图片关联；无法关联的图片仍作为该好友的分析证据保存。

## JSON

支持消息数组位于根节点或 `messages`、`data`、`records`、`items`、`chatRecords`、`list` 字段。常见字段自动映射：

- 时间：`sentAt`、`timestamp`、`time`、`msgTime`、`createTime`、`date`、`datetime`、`发送时间`
- 发送者：`senderName`、`sender`、`nickname`、`from`、`user`、`username`、`发送者`、`昵称`
- 内容：`text`、`content`、`message`、`msg`、`body`、`消息`、`内容`
- 角色：`senderRole`、`role`、`isSelf`、`fromSelf`、`is_self`

无法识别的对象会保留解析提示，允许用户在预览中手工整理文本。

## CSV

CSV 使用带表头模式，常见中英文字段映射与 JSON 相同。支持 UTF-8、UTF-16、GBK/GB18030 等文本编码检测和宽松列数。

## HTML

HTML 会移除脚本、样式、iframe、对象和外链资源，只保留可见文本、时间行与图片文件名。外部资源不会自动访问。

## MHT / MHTML

MHT 作为 MIME 多段文件解析。HTML 正文进入聊天解析，内嵌图片附件提取为导入批次中的图片证据。解析后的提取文件只在预览期临时存在，提交后加密或清理。

## 图片与截图

支持 PNG、JPEG、WebP、GIF、BMP、TIFF。文件名包含“截图”“screenshot”“screen shot”的图片会标记为截图，可在导入预览中额外选择视觉模型识别文字。识别结果必须人工复核后提交。

无论是否在导入时识别截图，图片都可以保存在保险库中；分析时是否发送云端视觉模型由每次预检的独立授权控制。

## 明确不支持

- 直接读取 QQ/微信私有数据库或正在使用的客户端数据目录
- QQ `.db` / `.bak` 私有二进制格式
- 自动解密聊天数据库或绕过客户端安全机制
- 自动向 QQ、微信或其他平台发送消息

遇到新导出格式时，应新增适配器并添加脱敏夹具、编码、内嵌图片、损坏文件和重复导入测试。
